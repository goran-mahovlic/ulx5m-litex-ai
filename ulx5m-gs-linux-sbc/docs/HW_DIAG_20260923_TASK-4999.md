### Findings in the code (fixed, commit on branch mdio-100m-autoneg)

1. **TXC aligned with the data edge.** KSZ9031 DS00002117F, p. 22: "For the transmit path … the KSZ9031RNX does not add any delay locally at its GTX_CLK, TX_EN and TXD[3:0] input pins, and expects the GTX_CLK delay to be provided on-chip by the MAC." `fixed_100m` sent TXC = DDR(1,0) on the same `eth_tx` clock as TXD/TX_CTL → the PHY samples exactly on the transition (at best TX_ER on the last nibble, so the FCS is bad). **Fix:** `--tx-clk-src pll90`: PLL#1 CLK0 = data, CLK90 = TXC (+10 ns); both edges have ≥10 ns setup and hold. CLK90 goes to the pin directly (GateMate allows only one DDR clock per IO bank: "DDR port use signal different than already occupied DDR source").
2. **Link state from in-band status.** The datapath read `link_1G` from the RGMII in-band status, which in the bad state was S=2/S=3 → switch to gigabit framing. **Fix:** for `fixed_100m` the state is constant 100M (TX and RX).
3. **PHY reset 16 µs.** `LiteEthPHYHWReset` 256 cycles; DS Table 7-4: tSR ≥ 10 ms; the XI clock starts only with FPGA configuration, and RGMII_RST_N = IO_EB_B3 directly (no RC). **Fix:** `--phy-reset-ms 20`.
4. **Core voltage model.** VDD_CORE is selected by a jumper (open = 0.9 V, 1-2 = 1.0 V, 2-3 = 1.1 V; power.kicad_sch). The builds were made for SPEED (1.1 V); the same diag build in `fpga_mode=1` (0.9 V): **sys 13.57 MHz FAIL @ 16 MHz**. **Fix:** `--perf-mode lowpower` (PLL PERF_MD + nextpnr `fpga_mode=1`), sys 12.5 MHz, and because of that `--tx-store-forward` (PacketFIFO in eth_tx; `sim/tb_rgmii_tx_sf.py`: without it the frame falls apart into 35 pieces).
5. Diagnostics (`--diag`) now run in the clk25/2 domain (no PLL) and also measure the sys clock (`SYS=`).

### 2. Design error: XI (IO_EB_A3) in `--diag` builds depends on the sys PLL — FIXED

In `--diag` mode IO_EB_A3 is a `CC_IOBUF` with `T = ~refclk_oe`, and `refclk_oe` was a register in the **sys** domain.
LiteX `GateMatePLL` holds sys in reset until `USR_PLL_LOCKED` is 1 (`AsyncResetSynchronizer(cd, ~locked)`),
so **XI had no clock whenever the sys PLL did not lock**. diag6 is a SPEED build, and at 1.1 V its sys PLL is in
OVF (above), so today diag6 does NOT give an XI clock. This explains why "it worked yesterday, not today".
Fix: `refclk_oe` in the `refoe` domain (clk25, reset only `CC_USR_RSTN`). Regression test:
`sim/test_refclk_oe.sh` (RED before: "refclk_oe set in: always @(posedge sys_clk)", GREEN after).
Note: s7 and the g-builds had sys without a PLL (div2), so this fault did not affect them.

### 3. XI is driven OUTSIDE the KSZ9031 specification (schematic + datasheet) — main finding

`tools/kicad_netlist.py` on `ulx5m-gs-hw` (61b6709):
- `ETH_CLK` = **U4.E16 IO_EB_A3 ↔ U14.46 XI ↔ R104.2** (direct DC connection; X1/R104/C118 are not fitted).
- Bank EB: `VDD_EB` = **+1V8** → IO_EB_A3 gives at most **1.8 Vpp**.
- KSZ9031 `AVDDH` (U14.1/12) = **+3V3 via FB1** — XI/XO are in the 3.3 V domain.
- X1 = ECS-2520MV-250 powered from **+3V3** (the intended oscillator would give 3.3 Vpp).

DS00002117F, p. 66 (ch. 10): *"If the 25 MHz reference clock is provided externally, the XI input pin should
have a minimum clock voltage peak-to-peak swing of **2.5 V**. If VPP is less than 2.5 V, **series capacitive
coupling** is recommended. With capacitive coupling, the VPP swing can be down to 1.5 V."* + jitter < 100 ps.

→ 1.8 Vpp with DC coupling is **below the 2.5 Vpp minimum**. The oscillator input threshold in the 3.3 V domain is ~AVDDH/2 ≈ 1.65 V,
so the high level (1.8 V) has ~0.15 V of margin: operation is marginal and depends on temperature and noise. This matches all
observations so far:
- 2026-09-23: DRIVE=3 → PHY does not respond, DRIVE=6 → PHY ID readable (sensitivity to amplitude/edge);
- 2026-09-23 17:56 link 100FD, and from 18:05 **flapping** (reg1 0x796F ↔ 0x794B) with the same bitstream;
- 2026-09-24 10:55 (s7): PHY ID correct (digital part works), but **link 0 and partner 0** (analog part / AN);
- the same bitstream gives a different outcome over time.
The client's design (README) worked with the **ETH oscillator** (3.3 V), not with a clock from the FPGA.

Software cannot raise the level above VDD_EB = 1.8 V: DRIVE=12, SLEW=fast and CC_ODDR (b64, x2) only reduce
edge steepness and jitter, not amplitude. Tried today with no frames on the wire: x1 (comb, DRIVE 6), x2 (CC_ODDR, DRIVE 12),
x3 (comb, DRIVE 12), y1–y3, z1–z3: 0 frames, ping 0/5.

**Hardware change needed (one of two):**
1. **AC coupling:** cut the ETH_CLK trace between IO_EB_A3 and XI (near U14.46) and insert a series capacitor
   (e.g. 10–100 nF, 0402). Then 1.8 Vpp ≥ 1.5 Vpp (DS). The design stays the same (IO_EB_A3 = 25 MHz output, DRIVE 12).
2. **The PHY's own oscillator:** fit X1 (ECS-2520MV-250, 3.3 V), C118 (100 nF) and R104 (27 Ω), and **disconnect**
   IO_EB_A3 from ETH_CLK (cut the trace). Without disconnecting, 3.3 V from X1 goes to a 1.8 V bank pin: the protection diodes
   clip the level to ~2.3 V, so XI is again out of spec and the FPGA is overloaded. In the design then use `--no-phy-refclk`.

3. permission for ILA (`+uCIO`) with confirmation that `openFPGALoader -r` resets the FPGA (SRST ↔ RST_N on the carrier board).
With any of these channels the sequence is: mdioprobe (ID, reg1/1F before and after the write) → t1 (LiteEth with fixes).
